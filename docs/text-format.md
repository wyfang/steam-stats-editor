# 纯文本清单格式

状态：设计草案，尚未实现。目标是让用户和 AI 都能读写，使用 UTF-8 `.txt`，不需要 JSON 引号、表格或专用编辑器。

## 基本结构

以下仅为虚构语法示例，不能直接导入真实游戏：

```ini
# 保留实际导出的 appid 和字段 ID，仅修改目标数值。
format = steam-stats-v1
appid = 123456

[stats]
example_total_actions = 120
example_total_wins = 0
example_ratio = 0.75
```

| 项目 | 计划语义 |
| --- | --- |
| `format` | 必须为支持的格式版本，目前草案为 `steam-stats-v1` |
| `appid` | 必须与当前打开游戏一致，不允许通过修改它跨游戏套用字段 |
| `[stats]` | 唯一数据区段；头部必须位于它之前 |
| `字段ID = 数字` | ID 使用实际读取的精确字符串，区分大小写；数字是最终目标值 |
| `#` | 整行或行末注释；不能承载可执行指令或覆盖真实字段定义 |
| 空白行与等号两侧空格 | 允许，不影响含义 |
| 遗漏或删除赋值行 | 保持该字段不变 |
| `= 0` | 明确设置零目标，仍须满足字段本身的限制 |

字段顺序不影响执行。文本不得含 Markdown 代码围栏、自然语言指令、多个数据区段或重复赋值。数字使用小数点，不使用千位逗号；拒绝 `NaN`、无穷大、溢出和无法按实际类型表达的目标。是否接受科学计数法及具体长度上限需在解析器实现时定稿并测试。

## 导出内容

软件应遍历当前 SAM 实际读取到的 schema，而不是固定维护 CS2 字段清单。每个字段附近输出便于阅读的注释，包括显示名称、精确 ID、类型、读取到的当前值、最小与最大值、`maxchange`、`incrementonly`、保护、权限及可信服务器限制。

可读取字段导出当前值作为初始目标。只读字段可用明确注释标示；原值未变时允许完整清单回导，试图改变时必须拒绝。不可读取或格式无法安全表达的字段只输出说明，不编造数值或截断 ID。

目标文件中的注释是说明文本。导入时必须再次从当前游戏定义取得限制，不能接受用户在注释中改写 `protected=0` 或增大 `maxchange` 来改变校验。

## 导入校验

先完成全文件语法检查，再按当前游戏实际字段进行语义检查；两阶段均采用整份成功或整份拒绝，错误列表包含行号、字段 ID 和原因。

- 缺失或不支持的格式版本、错误 App ID、重复头部、未知区段、额外等号、空目标均阻断。
- 字段必须真实存在，精确 ID 大小写敏感；重复字段即使数值相同也阻断，不使用“最后一项覆盖”。
- 整数遵循实际整数范围，浮点值按 Steam 使用的实际精度验证，不能静默舍入为另一个目标。
- 越界、违反只增规则、改变只读字段、当前值不可读等均阻断。
- `maxchange` 不能直接放行远目标；符合其他规则的远目标可以进入分步计划，但必须标示为需要多轮验证的目标。
- 不包含任何实际差异时提示无需更改；不发起写入。

## 给 AI 的编辑要求

> 以这份软件导出的清单为唯一字段来源。保留 format、appid 和精确字段 ID，只修改我指定字段的等号右侧数字。遵守注释中的类型、范围、只增与只读要求，不补造字段，不添加 Markdown 代码围栏。返回纯文本，未指定字段保持不变。对不确定的目标先指出问题，不假定服务器一定接受。

AI 输出仍属于不可信输入，必须通过与人工编辑完全相同的导入校验。真实个人清单在本机保存，不作为仓库示例或测试夹具。
