# 需求与验收范围

状态：设计阶段，尚未实现。此文档是后续实现与验收依据，不是已经完成的功能说明。

## 目标

在 Windows 版 SAM 的统计数据界面增加导出与导入，使用户不用逐项填写界面。用户可以在普通文本编辑器中修改数据，也可以让 AI 基于导出的字段清单生成目标文件。对于不能单次达到的目标，提供经过约束校验、可观察且可停止的分步提交。

以软件本次实际读取的游戏字段定义和值为权威，支持不同游戏；CS2 仅为需求示例，不固定字段数为 286 或任何其他数量。用户手工清单可能不完整，不能成为代码内置字段表或完整性判断依据。

## 计划流程

1. 用户打开游戏，等待读取字段定义和当前统计值。
2. “导出清单”保存 UTF-8 纯文本，包含格式版本、App ID、字段 ID、当前值与只读限制注释。用户保留原始文件，并另存目标文件。
3. 用户或 AI 只修改目标数字。保留精确字段 ID，允许删除不需要修改的赋值行。原始和目标文件均由用户在本机管理。
4. “导入清单”先解析并依据当前实际字段验证。任何格式、游戏不匹配、未知字段、重复字段或无效数值错误，均阻断整份导入，显示行号和原因，不部分填入。
5. 预览只显示本次实际差异，包含字段名称、精确 ID、类型、当前值、目标值、限制与预计轮数。确认后填入界面，仍不写入 Steam。
6. 独立选择普通提交或“分步提交”。提交前重新读取当前值，防止预览之后数据发生变化。成就修改不自动混入统计批次。
7. 运行期间显示阶段、字段进度、轮数、等待倒计时和日志。“停止”阻止后续轮次；已发出的请求可能完成，需要继续处理对应回调及读回结果。

## 范围与限制

- 新增文本功能仅处理整数与浮点统计数值。保留上游成就界面，成就批量导入不在本轮计划内。
- 支持 `0` 目标。遗漏字段表示保持不变，不解释为清零；没有数值的赋值行属于错误。
- 类型、范围、单调递增、保护、权限与可信服务器要求来自当前实际字段定义。注释仅供阅读，导入不能信任用户改写的限制。
- 平均速率、受保护、权限不明或受限、只能由可信服务器设置的字段计划只读。未知字段类型也不能推测为可写。
- 字段无法读取时显示不可读原因，不能自动假定当前值为零，不能据此制定提交计划。
- 全部导入检查通过后才修改界面；导入与确认预览不会提交到 Steam。
- 导出文件和日志可能包含用户游戏数据，不自动上传或提交 Git。用户示例、真实账户值与个人目标清单不进入项目仓库。
- 不安装后台服务、不安排 Windows 自动启动。恢复功能初步采用重新打开、读当前值和重新导入目标文件后显式开始；是否增加本机任务保存可后续讨论。

## 后续验收

| 层次 | 必须验证的行为 |
| --- | --- |
| 离线格式测试 | UTF-8 与注释、完整导出回导、零值、遗漏、错误行号、重复 ID、未知 ID、错误 App ID、非法数值与整份拒绝 |
| 离线约束测试 | 整数与浮点边界、只读字段、单调递增、范围、步幅、无法表示的浮点目标、长任务估算 |
| 离线提交流程测试 | 请求被拒绝、回调失败与超时、迟到或重复回调、读回不一致与无进展、停止、断线和恢复 |
| Windows 构建与界面 | Windows 上构建成功；导出、导入、预览和取消不写账户；运行时界面响应、日志与停止行为符合设计 |
| 真实 Steam 小范围验证 | 实现后先展示具体游戏、字段、原值、目标值与影响，经用户确认再验证读取、提交回调和读回。不能用普通请求返回值代替成功证据 |

当前未运行上述新增功能测试，没有宣称 CS2 实际提交成功。Windows 构建成功也不能替代真实客户端兼容性验证。

## 实现前待确定

- 提交间隔暂以 120 秒作为建议起点，不作为官方限制。Steam 官方文档已核对：建议分钟级调用，但未公开固定限流阈值；后续需要验证实际表现。详见 [官方提交机制研究](./steam-submission-research.md)。
- 研究按错误类型退避、读回实际值后重新计算及有限次数的间隔调整；即使测得某一间隔成功，也不能保证它长期或跨游戏成立。
- 超时阈值、有限次数退避和无进展停止策略需在状态机实现前确定。默认设计应停止并说明原因，避免无限重试。
- 原版 `Commit Changes` 与新增分步提交的交互隔离方式需结合现有界面审查，避免成就或未预览的字段被一起提交。
